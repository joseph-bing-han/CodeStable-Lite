# CodeStable Lite 当前规格

## 项目是什么

CodeStable Lite 为软件演化提供单一 `cs` 入口：按用户当前诉求选择讨论、理解、设计、实现或收尾，用业务文档保存目标与事实，用 Task 记录执行和恢复过程。

这份规格目前只覆盖本次已核对的开发流程边界，不代表已经盘点项目全部能力。

## 文档与执行各自负责什么

- Issue 保存可关闭行动的目标、范围、方案、验证依据和结果。
- Project Spec 保存当前成立的稳定事实；尚未实现的目标不能作为当前能力。
- Epic 按需承载有界变化的活规格，不是每次修改的必需品。
- Task 是执行账本，保存步骤、进度、验证和恢复证据；归档不自动授权关闭业务事项。
- 简单 Question 可以直接回答，不创建空壳 Task 或业务文档。

## 当前流程漂移

2026-09-12 核对发现：技能仍要求先创建 Task 再分析和写业务文档，快改仍允许完成代码与验证后才创建 `ff`，并且没有完整规定 Task 归档后的关联状态回写。

这些现有指令与用户确认的开发顺序冲突。修正目标、边界及验收依据已前置记录到 [Issue 004](../issues/004-o-enforce-development-lifecycle.md)；本次修复尚未实施，不能宣称新流程已经落地。

## 保持的执行边界

Task Markdown 是唯一运行正本，原生 Todo 只是镜像。更新使用 SHA-256 陈旧快照保护，完成后通过 runtime 原子归档；已归档 Task 不复活、不倒填历史。

提交、推送、部署、破坏性操作和业务实体正式关闭分别遵守授权边界，不能由普通执行进度隐式授权。
